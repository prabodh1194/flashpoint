02What changes

You already run Spark. This gives it a warehouse face.

The engine stays Apache Spark. What changes is the layer your team works in.

Spark today

  • Notebooks stapled to a long-lived cluster
  • Job logs instead of a query profile
  • A cluster bill you cannot attribute per query

Spark with Flashpoint

  • A worksheet, and warehouses you create, suspend and resize
  • An operator-tree query profile for every query
  • Per-second metering, and a cost center beside the AWS bill
03Your stack

It plugs into what you already run.

No new engine to learn and no rewrite. A warehouse exposes one Spark Connect endpoint and one REST control plane, and everything else in your stack already speaks those.

Clients

  • Any Spark Connect client, including PySpark and notebooks
  • SQL through the REST gateway, or straight to the endpoint
  • Existing DataFrame and Spark SQL code, unchanged

Automation

  • Airflow, CI or a script drives lifecycle and queries over the REST API
  • Every query profile is a stable URL you can paste into a PR or a ticket
  • Metering per warehouse, readable next to the AWS bill

09Questions

Straight answers.

How close is it to Snowflake?

It copies the shape of the product: the warehouse, the worksheet, the query profile, the per-second billing. Your data stays in open formats, so there is nothing to migrate back out of.

What does it cost?

Per compute-second on a running warehouse. Suspended warehouses bill nothing. Sizes run on a published rate card from $0.08/h for one executor. There are no credits and no per-seat fees.

Where does my data live?

In your AWS account: Iceberg tables and Parquet results on your S3, catalog in your Glue, state in your DynamoDB. Nothing leaves the account.

Can I use it from a notebook or pandas?

Yes, anything that speaks Spark Connect can attach to a warehouse's gRPC endpoint. The REST gateway is there for SQL and lifecycle calls.
